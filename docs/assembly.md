# 組み立て手順

## 1. 現物を確認する

部品を [部品表](parts.md) と照合し、基板型番・リビジョン、電子ペーパーFPC印字、
LCDケーブルの端子を記録します。基板10942と10646を取り違えないよう役割のラベルを貼ります。
未確認事項を [検証記録](validation.md) に残します。

## 2. ESP32だけで通信を確認する

1. 下向きピンヘッダを取り付ける前に、ブレッドボードの溝と列の間隔が合うか仮置きします。
2. USBで各基板を単独起動し、[開発環境](development.md) の設定でスケッチを書き込みます。
3. `hirofumi/config.h` のDeep Sleepを一時OFF。画面・タッチはまだOFFです。
4. シリアルに表示される2台のSTA MACをそれぞれの `secret.h` に登録し、再度ビルド・書き込みします。
5. 弘文側シリアルで `c` を送信。待機部屋側にCALL、弘文側にRECEIVEDが出ることを確認します。
6. 待機部屋側で `c` を送信。弘文側にCONFIRMEDが出ることを確認します。
7. 相手を電源OFFにした試験も行い、応答なしを成功表示にしないことを確認します。

## 3. 飲んだ・呼出ボタンとLEDを接続する

電源を外し、[回路・配線図](wiring.md) のとおりにボタン2個と飲水LEDを接続します。
大型タクトの接点対を導通試験し、ボタンには「飲んだ」「呼出」のラベルを付けます。
同じスイッチ型番でも、キャップ色・間隔・ラベルで区別してください。

`DRINK_INTERVAL_SECONDS` を机上試験用に60秒へ短縮し、点灯→飲んだ→消灯→再点灯を確認します。
短押し、長押し、連打、2個同時押し、押したまま起動を試します。
試験終了後は60分へ戻します。同時押しは現行実装では飲水記録と呼出の両方を処理します。

## 4. 待機部屋側のLEDとサウンダーを接続する

LED3枝それぞれに1kΩを入れ、圧電サウンダーにも直列1kΩを入れます。
サウンダーは両面スルーホール基板へ直付けせず、ブレッドボード上に配置して別に固定します（メーカー実装条件）。
CALLで200ms ON / 800ms OFFになること、確認で両方が停止することを確認します。
最初は抵抗値を下げず、実際の設置位置から見え方・聞こえ方を評価します。

## 5. 画面とタッチを確認する

[画面確認手順](display-bringup.md) を先に実施します。
電子ペーパーは解像度だけでドライバーを選ばず、FPC/コントローラーとメーカーサンプルを照合します。
表示と通信を個別に確認した後で統合します。

## 6. 時計・Deep Sleep・電池を確認する

弘文側 `secret.h` にWi-Fi情報を入れてコールドブートし、日本時間の次回予定を確認します。
SSID/PASSWORDそのものをシリアルへ出しません。
7時・21時の切替は一時的に設定時刻を近い値へ変えて試験し、終了後に戻します。
通信中にAPへ接続しない構成であることも確認します。

Deep SleepをONに戻し、USBを外して指定電池入力から給電します。
タイマー復帰、GPIO0/1の復帰、LED保持、電池交換後の再同期を確認します。
消費電流は「待機」「LED点灯」「画面更新」「送信」の各状態で測り、実測値を記録します。

## 7. 仮固定して現地試験を行う

アクリル板に電子ペーパー、操作基板、ESP32、ブレッドボード、電池箱を実寸で並べます。
最初はアセテートテープで固定し、はんだ面と金属部を絶縁します。
ボタンを押して基板がしなったり、配線が抜けたりしないように支持します。
電池交換、USB接続、RST/BOOTの操作ができる余白を残します。

弘文さんの部屋と待機部屋に実際に置き、扉の開閉や人の位置を変えて通信試験をします。
100回、できれば1,000回程度のCALL→RECEIVED→CONFIRMEDを記録し、
失敗数・再送数・RSSI・配置をまとめます。自動耐久試験用の送信ループは今後追加します。
基準を満たす配置が見つからない場合に、設置位置変更や中継器を検討します。

運用が安定してからスペーサー＋M2ネジへの変更やケース寸法を決めます。
