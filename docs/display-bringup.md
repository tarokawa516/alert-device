# 画面・タッチの確認

初期状態では両 `config.h` の画面/タッチをOFFにしています。
ライブラリを導入してコンパイルできることと、購入したモジュールが動くことは別なので、
以下の順で確認してから有効化します。

## 弘文さん側：Pico-ePaper-2.66 / Waveshare 20052

型番・基板名・FPC印字を記録します。白黒296×152であることを再確認し、3色版と混同しません。
参考の一次資料は [メーカーのPico用サンプル](https://github.com/waveshareteam/Pico_ePaper_Code/blob/main/python/Pico_ePaper-2.66.py) と
[製品Wiki](https://www.waveshare.com/wiki/Pico-ePaper-2.66) です。

現在の `hirofumi/display.h` は `GxEPD2_266_BN` を仮に接続する日本語画面アダプターです。
このクラスが対象とするのは **DEPG0266BN / SSD1680** であり、
**Waveshare 20052へ対応すると確認できたわけではありません**。
FPC/コントローラーが異なる場合は、公式 `EPD_2in66` ドライバーのESP32への移植や適切なドライバーへの差し替えを先に行います。
GxEPD2で同じ解像度が選べるだけでは適合の根拠になりません。

1. `config.h` とGPIO表に合わせて配線し、VCC=3.3VとGNDを確認する。
2. 正しいドライバー単体で白→黒→文字→sleepを試す。BUSYの極性と更新完了を確認する。
3. 回転後に296×152となること、日本語の欠け・端の切れ・上下反転を確認する。
4. 画面更新後に駆動電源がOFFになることを測る。
5. 以上を記録してから `ENABLE_DISPLAY=true` で統合試験する。

初期アダプターは全面更新のみです。Deep Sleep前後のRAM保持や前フレーム復元が未確認のまま高速部分更新は使いません。
同期描画中の短押し取りこぼし対策、文字サイズ・コントラストの弘文さん本人による評価も残っています。

## 待機部屋側：1.9inch Touch LCD / Waveshare 31122

[製品資料](https://www.waveshare.com/wiki/1.9inch_Touch_LCD) はST7789V2、172×320、CST816です。
初期アダプターはAdafruit_ST7789とCST816のI²C読み出しを使います。

1. SH1.0 12ピンケーブルの各端子を確認する。LCD_DINはESP32のMOSIへつなぐ。
2. LCD_RSTとTP_RSTをGPIO3で共有する案が現物回路でも成立することを確認する。
3. `ENABLE_DISPLAY=true`、タッチはOFFのまま文字・画面端・色・バックライトを試す。
4. `ENABLE_TOUCH=true` とし、I²Cアドレス0x15への応答とレジスタ0x02のタッチ数を確認する。
5. 待機中に触れたままCALLを受けても確認しないこと、いったん離して触れると確認することを試す。
6. タッチ未接続・I²C異常でも通知ループが止まらないことを確認する。

現行コードは新しいタッチを画面全体で受け付けます。表示された確認枠に限定した座標判定は未実装です。
タッチ制御の自動スリープ・復帰条件は現物とメーカーサンプルで確認し、
ポーリングが不安定ならIRQを使う配線案に見直します。その場合はGPIO表も更新します。
