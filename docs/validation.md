通信テストは既知のバイト列との一致、エンディアン、全4種別、32bit最大値、
短すぎる/長すぎるフレーム、magic/version/type/ゼロIDの拒否、MACの形式、別イベントの識別を検査します。
コンパイラーがstatic_assertを評価するため、ターゲットCPUで実行せずに検証できます。

```text
g++ -std=c++17 -Wall -Wextra -Werror -fsyntax-only tests/protocol_tests.cpp
```

今回の実行にはESP32コア付属の `riscv32-esp-elf-g++` を使用。
ビルドは `scripts/build.ps1 -ExampleSecrets` および `-ExampleSecrets -EnableDisplays`。
実際のSSID/PASSWORDは使用していません。
ボードは `esp32:esp32:esp32c3`、USB CDC有効、Flash 4MB、Defaultパーティション。
アプリ上限は1,310,720 bytes。画面有効時はFlash余裕が約9～10%なので、機能追加時にサイズを再確認します。
RAMの上記値は静的領域で、無線・描画の実行時ヒープ/スタック測定は含みません。
画面有効のビルド成功はEPDドライバーの現物適合やタッチ動作の保証ではありません。
